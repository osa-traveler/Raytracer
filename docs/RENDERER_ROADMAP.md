## 1. 開発方針（Claude Codeと共有する約束）

1. **自作レンダラーが主役**。Blenderはシーン作成・調整と比較用のCyclesに使う。自作の光輸送をCyclesに委譲しない。
2. **アルゴリズムを入れ替えられる設計**にする。Classic、PT、PT+MIS、Photon Mapping/PPMなどを同じシーンで比較できるようにする。
3. **一度に1つの概念を追加**する。機能追加前後で、何が変わったか説明・測定できるようにする。
4. **正しさと速さを分けて考える**。先にシンプルな参照実装を作り、その後に高速化する。
5. **画像は線形色空間で蓄積**し、表示時に露出・トーンマッピング・sRGB変換する。計算途中で表示用RGB値を直接平均しない。
6. **物理的に整合する重み付け**を意識する。BRDF/BSDF、余弦項、PDF、距離減衰、可視性、エネルギー保存を区別する。
7. **再現性を確保**する。乱数シード、spp、解像度、反射回数、レンダラー設定を画像とともに残す。
8. **完了の根拠はテストと画像**。コードが書けただけではDoneにしない。
9. 技術史の観察が目的。新しい手法が必ず古い手法より良いとは決めつけず、**得意・不得意を比較**する。
10. Claude Codeは、変更前に既存コードを確認する。使用言語、Scene形式、UI構成、現行機能を推測で決めつけない。

### 共通アーキテクチャの目標（必要に応じて段階的に整理）

```text
Blender（配置・材質・ライト・カメラ）
    ↓ scene export / 自作シーン読み込み
Scene / Geometry / Camera / Lights / Materials
    ↓
Intersection / Acceleration structure（将来的にBVH）
    ↓
Integrator（Classic / PT / PT+MIS / PPM / ...）
    ↓
Sampler + Film（線形HDR、spp蓄積、補助バッファ）
    ↓
Exposure / Tone mapping / sRGB / 保存・プレビュー
```

**補助バッファ（AOV）候補**：直接照明、間接照明、発光、反射、法線、深度、アルベド、サンプル数。すべてを最初から実装する必要はない。

### M1 — 面光源とソフトシャドウ

**実装**
- [x] 面光源（まず矩形）をシーンに定義する。Blenderから出力できない照明属性は独自メタデータで補う。（Blenderのカスタムプロパティ → glTF extras。読み込みのみで、描画にはまだ使っていない。[CURRENT_IMPLEMENTATION.md](CURRENT_IMPLEMENTATION.md) の「5. 光源」）
- [ ] 光源表面をランダムサンプリングし、シャドウレイで遮蔽を判定。
- [ ] 光源面積、法線、距離、PDFを考慮した直接照明の推定器を実装。
- [ ] 光源サイズとサンプル数を変更できるようにする。

**実験**：小さい面光源と大きい面光源で、球の影を1/4/16/64サンプル比較。

**完了条件**：光源サイズに対応して半影が変化し、サンプルを増やすとノイズが減る。

### M2 — 最小のモンテカルロ・パストレーシング

**実装**
- [ ] Lambert拡散BSDF、コサイン重み付き半球サンプリング。
- [ ] カメラから始め、反射方向を確率的に選ぶ経路追跡。
- [ ] 各反射で `BSDF × |cosθ| / PDF` をスループットに掛ける。
- [ ] 発光面・環境光への到達を寄与として扱う。
- [ ] 反射回数を0/1/2/4/8で切り替える。初期版はNEEなしでもよい。
- [ ] Classic方式の直接照明との**二重計上を避ける**。

**実験**：Cornell Box（赤壁・緑壁・白床・天井面光源）。反射回数ごとの色移りを比較。

**完了条件**：直接照明だけでは出なかった間接照明・カラーブリーディングを確認できる。サンプル増加で収束傾向がある。

### M3 — Progressive Rendering（漸進表示）

**実装**
- [ ] 1ピクセルあたりの放射輝度の合計とサンプル数を保持。
- [ ] レンダリングしながら、1→4→16→64→256 sppで表示を更新。
- [ ] カメラ・材質・光源変更時に蓄積を無効化／リセット。
- [ ] 乱数シードと反復番号で、再現性のある比較を行えるようにする。

**実験**：同一画角でspp増加のタイムラプス／連番画像を保存。

**完了条件**：画面を再起動せずにサンプルを追加でき、計算を続けるほど安定する。

### M4 — サンプリング効率：NEE・Importance Sampling・MIS

**実装**
- [ ] Next Event Estimation（交点から光源を直接サンプリング）。
- [ ] 光源サンプリングとBSDFサンプリングのPDFを正しく計算。
- [ ] Multiple Importance Sampling（まずPower Heuristic）。
- [ ] 鏡面反射などdelta成分では、MISの扱いを適切に分岐。
- [ ] Russian Rouletteによる経路終了（生存確率に応じて重み補正）。
- [ ] 計算時間／spp／ray数をログに記録。

**実験**：小さな面光源、鏡面の多いシーンで `PTのみ / PT+NEE / PT+MIS` を同時間比較。

**完了条件**：比較画像に系統的な明るさの差（二重計上など）がなく、得意なシーンではMISが低ノイズになる。

### M5 — BVH・並列化・計測基盤

**実装**
- [ ] メッシュの三角形に対するBVH構築と走査。
- [ ] 最近傍ヒットと遮蔽判定の両方を高速化。
- [ ] ピクセル／タイル単位でCPU並列化。乱数状態はワーカー間で安全に分離。
- [ ] BVHなし／あり、シングル／マルチスレッドを比較。

**実験**：高ポリゴンメッシュ、Cornell Box、広い建築シーンで交差判定数・秒数を比較。

**完了条件**：画質を保ったまま高速化でき、単純なシーンで数値的一致も確認できる。

> M5は学習順序の都合上ここに置く。複雑なモデルが先に必要なら、M2以前に前倒しして構わない。

### M6 — 古典的Photon Mapping → PPM / SPPM

**実装**
- [ ] 光源からフォトンを放出し、表面で確率的に反射／吸収。
- [ ] フォトンの位置とエネルギーを記録し、近傍密度推定で間接照明を計算。
- [ ] フォトン数・探索半径と、ノイズ／ぼけ（バイアス）の関係を観察。
- [ ] Progressive Photon Mapping：反復計算し、蓄積に応じて探索半径を縮小。
- [ ] 余裕があればSPPM（確率的なカメラ経路を再サンプル）。

**実験**：ガラス球によるコースティクス、狭い開口から照らされる部屋。Classic PM / PPM / PT+MISを同時間比較。

**完了条件**：フォトン密度不足による粗さ、探索半径によるぼけ、PPMの改善を説明・可視化できる。

### M7 — PBRマテリアル：Fresnel・GGX・透過

**実装**
- [ ] Fresnel（Schlick近似等）と材質別反射率。
- [ ] GGX等のマイクロファセットBRDFと対応するサンプリング・PDF。
- [ ] Roughness / MetallicのパラメータをBlenderと対応付ける。
- [ ] ガラスの反射・屈折、全反射、必要なら透過BSDF。
- [ ] 拡散＋鏡面の重みを物理的に矛盾なく扱う。

**実験**：粗さ0.05〜1.0の球列、金属／非金属、ガラス球のコースティクス。

**完了条件**：粗さ・金属度・屈折率の変更が期待どおりに反映され、エネルギーの不自然な増大がない。

### M8 — HDRI・テクスチャ・複雑なシーン

**実装**
- [ ] HDR環境マップによる照明と、可能なら明るさに応じたImportance Sampling。

**実験**：金属球＋HDRI、Stanford Bunny、Sponza等の建築シーン。

**完了条件**：自作プリミティブだけでなく、現実的な材質を持つ複雑なシーンを描ける。

- [ ] 空間・方向ごとの入射光分布の統計を集める。

- [ ] 混合PDFを正しく使い、寄与推定のバイアスを避ける。

**完了条件**：難しい間接照明で、同時間・同誤差の比較に改善を確認できる。

## 3. 比較実験の共通ルール

### 固定しておくもの

- シーン、カメラ、解像度、照明、露出、トーンマッピング。
- 比較したい条件以外のマテリアルとBSDF実装。
- 乱数シード（同条件の再現が必要な比較の場合）。
- 反射回数やRussian Rouletteの設定。

### 比較を3種類行う

1. **同spp比較**：サンプルの質を比較。ただし1サンプルの計算コストが異なることに注意。
2. **同時間比較**：実用上の性能を比較。マシン・並列度も記録。
3. **参照画像との差**：高sppの参照レンダリングとのRMSE等を測る。Cyclesを使う場合は光源・BSDF・色変換の差に注意。

### 保存先の例

```text
experiments/
  2026-10-15_baseline/
    scene.blend                # 必要なら
    config.json                # render設定・seed・spp等
    output.png                 # 表示用
    output.exr                 # 線形HDR（対応後）
    notes.md                   # 観察と次の仮説
```

可能なら「処理時間」「発射レイ数」「ヒット数」「平均経路長」も記録する。**見た目だけでは、なぜ速く／遅く／綺麗になったか分からない**ため。

### 毎回の作業手順

1. ロードマップの「現在地」と最新実験ログを確認する。
2. その回に取り組むタスクを1つ選び、変更点と確認方法を決める。
3. 既存コードを確認し、必要最小限の変更を加える。
4. ビルド／テスト／レンダリング結果を確認する。
5. **何が変わったか**を、画像・数値・文章で記録する。
6. 完了条件に達したらチェックし、現在地と次の一手を更新する。

### 実装上の注意

- 全面的な書き換えを先にしない。比較可能な旧方式を残す。
- 新しい最適化は、無効化できるスイッチを用意する。
- アルゴリズム上の近似・バイアス・制限を記録する。
- 分からないことは「未確認」と記載する。結果が未計測なら数値を作らない。
- BlenderのMCP操作、シーンのエクスポート、自作レンダラーの実装を混同しない。

### 2026-10-15 — M1 手順1 / 面光源の定義と読み込み

- **目的**：矩形の面光源をシーンデータに持たせ、レンダラに読み込む（描画への利用は次の手順）。
- **実装変更**：GLB の `Area_Light` ノードの extras（`rt_light_type` / `rt_size_x` / `rt_size_y` / `rt_radiance`）と変換から、位置・辺ベクトル・法線・面積・明るさを読む（`AreaLight`）。描画は従来どおり、面光源の中心の点光源。
- **シーン・設定**：Untitled / Room_2Spheres。面光源は 2 m × 2 m、`rt_radiance` = 15（仮。手順3で較正）、中心 (-4, 5, 2)、発光の向き (0.667, -0.667, -0.333)。
- **比較条件**：基準画像との同一性（ビット単位）。
- **観察**：画像は2シーンとも基準と完全に同一（期待どおり）。発光の向きは、最初に「ローカル -Y」と誤って仮定し、Blender 側の値との照合で間違いに気づいた。正しくは「ローカル -Z」（glTF のカメラ・ライトと同じ）。テストに、Blender 側の値との照合を入れた。
- **保存先**：`experiments/2026-10-15_baseline/`（面光源の定義を JSON に追加して再生成）
- **結論・次の一手**：手順2（乱数とサンプラ）へ。

### 2026-10-15 — M0 / 現行実装の基準化

- **目的**：後から「何が改善したか」を正しく比べられる状態にする。
- **実装変更**：`Film`（線形HDR）と `Display`（表示変換）の分離。PNG／PFM出力、`--headless`／`--out`／`--repeat`／`--threads`、レイ数カウンタ、設定のJSON出力。コードを `raytracer.h`／`imageio.h`／`main.cpp` に分割。テスト69項目。
- **シーン・設定**：`Room_2Spheres.glb`（部屋＋金属球＋ガラス球）と `Untitled.glb`（＋青い拡散球）／640x480／1 spp（ピクセル中心、乱数なし）／max depth 6／点光源 (-4, 5, 2)・減衰なし／環境光 0.12／露出 1.0・ガンマ 2.2。
- **比較条件**：film導入前後の同一性（ビット単位）、スレッド数 1・3・8 での同一性。
- **計測**（Apple M1・8コア・Release・5回の中央値）：Room_2Spheres は 91.3 ms／852,655 レイ／BVH訪問 約90回・三角形判定 約20回（1レイあたり）。Untitled は 96.6 ms／849,315 レイ。1スレッドでは約 418 ms。同じ条件の再測定で時間は約10%揺れた（旧配置で 89.6 → 98.8 ms）。なお、両シーンとも配置・カメラを中央に直して再生成した（旧画像とは別物）。
- **観察**：film導入で画像は変わらない（期待どおり）。結果はスレッド数に依存しない。1ピクセルあたり約2.8レイ。1回だけ約1.3秒の外れ値があったが再現せず（原因未特定）。
- **保存先**：`experiments/2026-10-15_baseline/`（`run.sh` で再生成。`.pfm` は Git 対象外、SHA-256 を記録）
- **結論・次の一手**：M0完了。M1（面光源とソフトシャドウ）へ。乱数とサンプラが必要になる。
