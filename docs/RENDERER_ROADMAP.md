## 1. 開発方針（Claude Codeと共有する約束）

1. **自作レンダラーが主役**。Blenderはシーン作成・調整と比較用のCyclesに使う。自作の光輸送をCyclesに委譲しない。
2. **アルゴリズムを入れ替えられる設計**にする。Classic、PT、PT+MIS、Photon Mapping/PPMなどを同じシーンで比較できるようにする。
3. **一度に1つの概念を追加**する。機能追加前後で、何が変わったか説明・測定できるようにする。
4. **正しさと速さを分けて考える**。先にシンプルな参照実装を作り、その後に高速化する。
5. **画像は線形色空間で蓄積**し、表示時に露出・トーンマッピング・sRGB変換する。計算途中で表示用RGB値を直接平均しない。
6. **物理的に整合する重み付け**を意識する。BRDF/BSDF、余弦項、PDF、距離減衰、可視性、エネルギー保存を区別する。
7. **再現性を確保**する。乱数シード、spp、解像度、反射回数、レンダラー設定を画像とともに残す。
8. **完了の根拠はテストと画像**。コードが書けただけではDoneにしない。
9. 技術史の観察が目的。新しい手法が必ず古い手法より良いとは決めつけず、**得意・不得意を比較**する。
10. Claude Codeは、変更前に既存コードを確認する。使用言語、Scene形式、UI構成、現行機能を推測で決めつけない。

### 共通アーキテクチャの目標（必要に応じて段階的に整理）

```text
Blender（配置・材質・ライト・カメラ）
    ↓ scene export / 自作シーン読み込み
Scene / Geometry / Camera / Lights / Materials
    ↓
Intersection / Acceleration structure（将来的にBVH）
    ↓
Integrator（Classic / PT / PT+MIS / PPM / ...）
    ↓
Sampler + Film（線形HDR、spp蓄積、補助バッファ）
    ↓
Exposure / Tone mapping / sRGB / 保存・プレビュー
```

**補助バッファ（AOV）候補**：直接照明、間接照明、発光、反射、法線、深度、アルベド、サンプル数。すべてを最初から実装する必要はない。

### M1 — 面光源とソフトシャドウ

**実装**
- [x] 面光源（まず矩形）をシーンに定義する。Blenderから出力できない照明属性は独自メタデータで補う。（Blenderのカスタムプロパティ → glTF extras。[CURRENT_IMPLEMENTATION.md](CURRENT_IMPLEMENTATION.md) の「5. 光源」）

### M2 — 最小のモンテカルロ・パストレーシング

**実装**
- [x] Lambert拡散BSDF、コサイン重み付き半球サンプリング。（`sampleCosineHemisphere()`。分布をテストで確認）
- [x] カメラから始め、反射方向を確率的に選ぶ経路追跡。（`pathTrace()`）
- [x] 各反射で `BSDF × |cosθ| / PDF` をスループットに掛ける。（Lambert + コサイン分布では、ちょうどアルベドになる）
- [x] 発光面・環境光への到達を寄与として扱う。（面光源は解析的に交差。環境光は `--env`、既定 0）
- [x] 反射回数を0/1/2/4/8で切り替える。初期版はNEEなしでもよい。（`--max-depth`。NEEなし）
- [x] Classic方式の直接照明との**二重計上を避ける**。（`--integrator classic|path` で完全に別経路）

**実験**：Cornell Box（赤壁・緑壁・白床・天井面光源）。反射回数ごとの色移りを比較。

**完了条件**：直接照明だけでは出なかった間接照明・カラーブリーディングを確認できる。サンプル増加で収束傾向がある。 → **達成（2026-10-15）**。`experiments/2026-10-15_m2-cornell/`

### M4 — サンプリング効率：NEE・Importance Sampling・MIS

**実装**
- [x] Next Event Estimation（交点から光源を直接サンプリング）。（`sampleDirectLight()`。NEEあり/なしで期待値の一致をテスト。Cornell Boxで同じsppの誤差が約1/4、`experiments/2026-10-15_m4-nee/`）
- [x] 光源サンプリングとBSDFサンプリングのPDFを正しく計算。（`lightPdfSolidAngle()`、`bsdfPdfLambert()`。どちらも立体角あたり。方向全体で積分すると1になることをテスト）
- [x] Multiple Importance Sampling（まずPower Heuristic）。（`--mis` / `--no-mis`、既定オン。BSDFのみ / NEE / MISの期待値の一致をテスト。大きい光源でNEEより約20%低ノイズ、`experiments/2026-10-15_m4-mis/`）
- [x] 鏡面反射などdelta成分では、MISの扱いを適切に分岐。（M7で実装。鏡・ガラスの後は、光源サンプリングをせず、その後に光源に当たったら重み1。鏡越しの光源、ガラス越しの光で期待値の一致をテスト）
- [x] Russian Rouletteによる経路終了（生存確率に応じて重み補正）。（`--rr`、3回反射から。期待値が変わらず（平均輝度の差0.01%以下）、レイ数は半分、`experiments/2026-10-15_m4-russian-roulette/`）
- [x] 計算時間／spp／ray数をログに記録。（JSONに、レイ数とシャドウレイ数を別々に記録。`experiments/analyze_m4.py` が表と効率を出す）

**実験**：小さな面光源、鏡面の多いシーンで `PTのみ / PT+NEE / PT+MIS` を同時間比較。

**完了条件**：比較画像に系統的な明るさの差（二重計上など）がなく、得意なシーンではMISが低ノイズになる。 → **達成（2026-10-16）**。期待値の一致はテストで確認し、大きい光源でMISが低ノイズになった。M7で鏡・ガラス・つやのある面を入れた後、鋭い金属でNEEのみが最悪、MISが全体で最良になることも確認した（`experiments/2026-10-16_m7-materials/`）。

### M5 — BVH・並列化・計測基盤

**実装**
- [x] メッシュの三角形に対するBVH構築と走査。（中央値分割と、binned SAH の2つ。既定は SAH。`--accel none|median|sah`）

**実験**：高ポリゴンメッシュ、Cornell Box、広い建築シーンで交差判定数・秒数を比較。

**完了条件**：画質を保ったまま高速化でき、単純なシーンで数値的一致も確認できる。 → **達成（2026-10-16）**。全方式で画像が完全に一致（RMSE 0）、ランダムな三角形で総当たりと一致をテスト。未実施：広い建築シーンでの比較（シーンがない）。

### M7 — PBRマテリアル：Fresnel・GGX・透過

**実装**
- [x] Fresnel（Schlick近似等）と材質別反射率。（金属 = base color を F0、非金属 = IOR から F0。ガラスは厳密なFresnel。`KHR_materials_ior` / `specular` を読む）
- [x] GGX等のマイクロファセットBRDFと対応するサンプリング・PDF。（GGX + height-correlated Smith、見える法線のサンプリング（VNDF）、混合PDF。多重散乱の補正つき。積分・相反性・エネルギーをテスト）
- [x] Roughness / MetallicのパラメータをBlenderと対応付ける。（glTF の metallic / roughness をそのまま使う。alpha = roughness²。同じシーンを Blender Cycles で描いて比較: 鋭い金属・鏡は 0.3% 以内で一致、他は 2〜5% 明るい、`experiments/2026-10-16_m7-cycles/`）
- [x] ガラスの反射・屈折、全反射、必要なら透過BSDF。（滑らかなガラスのみ。粗いガラス（透過BSDF）は未対応）
- [x] 拡散＋鏡面の重みを物理的に矛盾なく扱う。（鏡面ローブの方向アルベドを表にして、拡散の重みを `(1−Es(wo))(1−Es(wi))/(π(1−Ē))` にする。glTF 式は方向アルベドが 1.4 まで上がるので使わない）

## 3. 比較実験の共通ルール

### 固定しておくもの

- シーン、カメラ、解像度、照明、露出、トーンマッピング。

### 比較を3種類行う

1. **同spp比較**：サンプルの質を比較。ただし1サンプルの計算コストが異なることに注意。
2. **同時間比較**：実用上の性能を比較。マシン・並列度も記録。
3. **参照画像との差**：高sppの参照レンダリングとのRMSE等を測る。Cyclesを使う場合は光源・BSDF・色変換の差に注意。

### 2026-10-16 — M7 / PBR 材質（Fresnel・GGX・ガラス）

- **目的**：金属・非金属・ガラスを、物理的に矛盾なく（エネルギーを増やさず）パストレーシングで描く。粗さ・金属度・屈折率の変更が反映されることを確かめる。M4 の残り（delta 成分での MIS の分岐）も扱う。
- **実装変更**：`--bsdf lambert|pbr`（Lambert = 旧 M2 のモデル、ビット単位で再現。PBR = 既定）。PBR は glTF の metallic-roughness: 拡散 + GGX（height-correlated Smith、見える法線のサンプリング）、Schlick の Fresnel（f0 = 金属は base color、非金属は IOR と `KHR_materials_specular` から）、鏡（roughness < 0.032）とガラスは delta 成分。拡散と鏡面は、鏡面ローブの方向アルベド Es(μ)（起動時に作る表）で結合（エネルギー保存・相反性）。多重散乱の補正（Kulla–Conty、`--no-multiscatter` で切る）。ガラスは Fresnel の確率で反射 / 屈折（全反射、η² の補正）。delta の後は、光源サンプリングをせず、光源に当たったら重み 1。`KHR_materials_ior` / `specular` の読み込み。`--env-uniform`（白い炉）。
- **シーン・設定**：`Scene/Test/MaterialRow.glb`（金・赤いプラスチック、roughness 0.05〜1.0 の各7個、ガラス球 IOR 1.2 / 1.5 / 2.4、鏡、グレーの鏡）／640x480／ジッタ／シード 1／反射回数 6／空の光 0.5／Release ビルド。
- **比較条件**：同じ spp での BSDF のみ / NEE のみ / MIS（基準 = MIS 4096 spp）、多重散乱の補正の有無、白い炉。
- **計測**：白い炉の平均の放射輝度: 鏡 0.9996、ガラス 1.0000、金属 0.998〜1.003（補正なしでは roughness 0.75 で 0.65、1.0 で 0.39）、プラスチック 0.9987〜0.9999。256 spp の全体の RMSE（BSDF のみ / NEE のみ / MIS）: 0.0364 / 0.0529 / 0.0107。鋭い金属の列: 0.0346 / 0.1746 / 0.0129。
- **観察**：（1）glTF 仕様どおりの `(1−F(v·h))×拡散 + 鏡面` は、グレージング角で方向アルベドが 1.4 まで上がった（roughness 0.2、84°）。これを、Es(μ) による結合に改め、全角度で 1.000 以下にした。（2）単一散乱の GGX は、粗い金属で最大 61% のエネルギーを失う。補正で 1 に戻る（金属の列の平均で約 20% 明るくなる）。（3）鋭い金属では NEE のみが最悪、プラスチックでは BSDF のみが劣り、MIS はどちらでも最良（M4 の予想の確認）。（4）ガラス越しの光は、光源サンプリング（ガラスを不透明な遮蔽物として扱う）では拾えず、BSDF サンプリングだけが拾う（コースティクスは、ざらつく）。
- **テスト**：1959項目、すべて成功。数値積分との一致、相反性、エネルギー（白い炉、全角度）、スネルの法則、ガラス板越しの光のずれと Fresnel の減衰、3方式の期待値の一致（光沢面・ガラス越し）、鏡越しの光源。わざとバグを入れて検出を確認（拡散の結合を glTF 式に戻す、屈折率の向きを逆にする、VNDF の PDF から G1 を外す、多重散乱の項を落とす）。
- **保存先**：`experiments/2026-10-16_m7-materials/`、`..._m7-furnace/`、`docs/screenshots/2026-10-16_m7-*.png`
- **Cycles との比較**（`experiments/2026-10-16_m7-cycles/`、別プロセスの画面なし Blender 5.2、同じ光源・空・カメラ、1024 spp）：球ごとの比（このレンダラー / Cycles）は、鋭い金（roughness 0.05〜0.5）が 1.000〜1.003、鏡が 1.002、粗い金（0.75、1.0）が 1.026、1.047、プラスチックが 1.023〜1.050、ガラスが 1.020〜1.033。「厳密な Fresnel にすれば縮まる」という仮説は、実験で外れた（縮まらず、わずかに増えた）。原因は未解決。
- **未達・次の一手**：粗いガラス（つや消し、透過 BSDF）は未対応（滑らかなガラスとして扱う）。ガラスの影・コースティクスは M6（フォトンマッピング）の題材。Cycles との数 % の差の原因の調査。

### 2026-10-16 — M5 / 三角形の探し方、スレッド数、Release での測り直し

- **目的**：BVH の効果と、分割の方法(中央値 / SAH)、走査の工夫(近い子から、any-hit)の効果を測る。画質を保ったまま速くなることを確かめる。
- **実装変更**：`--accel none|median|sah`（BVH なし = 全三角形 / 中央値分割 / binned SAH、16 ビン）、近い子から先に走査（`--no-ordered` で切る）、Path の影レイの any-hit（`occluded()`、`--no-any-hit` で切る）、BVH 構築時間の記録（JSON `acceleration`）。既定は、SAH + 近い子から + any-hit。BVH の深さに上限（56）。
- **シーン・設定**：Cornell（30 三角形、パス + MIS 16 spp）、Room_2Spheres（7,948、classic 4 spp）、Untitled（11,916、classic 4 spp）、ビートル（301,716、classic 1・16 spp）／ジッタ／シード 1／8スレッド／Release ビルド／3回の中央値。
- **比較条件**：同じシーン・同じ設定で、探索方式だけを変える。画像は、BVH なしの画像との RMSE で比べる。
- **計測**：時間は `experiments/2026-10-16_m5-accel/notes.md` の表のとおり。主な値: ビートル 1 spp で、なし 80.6 s、中央値 18.2 ms、SAH + 近い子から 12.4 ms。Room で、なし 17.99 s、中央値 372 ms、SAH + 近い子から 134 ms。レイあたりの三角形判定は、Room で 7948 → 20.3（中央値）→ 2.0（SAH + 近い子から）。
- **観察**：**全方式で画像が完全に同じ**（RMSE 0）。BVH は大きいシーンで桁違いに効く。30 三角形の Cornell では、中央値の BVH は、総当たりより遅い（壁や床の大きな三角形が重なり、葉が絞れない）。SAH は、中央値の 2.5〜2.9 倍速く、構築は約 2.6 倍遅い（ビートルで 184 ms と 69 ms。読み込み時の1回）。近い子から走査で、さらに 8〜15%、any-hit で Cornell がさらに約 12% 速い。
- **スレッド数**（`..._m5-threads/`、16 spp）：4スレッドまでは効率 91% 以上、8スレッドで約 4.7〜4.8 倍（効率 58〜60%）。この Mac は性能コア 4 + 効率コア 4。
- **Release での測り直し**（`..._release-timings/`）：M2・M3・NEE の実験の時間は、Debug の約 18〜26 倍速かった。NEE は NEE なしの約 1.4 倍の時間。
- **保存先**：`experiments/2026-10-16_m5-accel/`、`..._m5-threads/`、`..._release-timings/`、`docs/screenshots/2026-10-16_m5-*.png`
- **結論・次の一手**：M5 完了（広い建築シーンでの比較は、そのシーンがないので未実施）。M6（フォトンマッピング）か M7（鏡・ガラスを Path に入れる）へ。

### 2026-10-16 — M4（Russian Roulette）/ 経路の確率的な打ち切り

- **目的**：反射回数の上限による暗さ（バイアス）をなくし、無駄なレイを減らす。期待値が変わらないことを確かめる。
- **実装変更**：`--rr`（3回反射から、生存確率 p = スループットの最大成分を [0.05, 0.95] に制限、続ける経路は 1/p 倍）。`--max-depth` は上限として残る。
- **シーン・設定**：Cornell Box／NEE（MIS なし）／64 spp／ジッタ／シード 1／基準 = ルーレットあり・上限 64 回・2048 spp（シード 99）。**Release ビルド**。
- **比較条件**：上限 8 回（なし）、上限 64 回（なし）、上限 64 回（あり）。
- **計測**：時間 6.2 / 9.2 / 4.4 s、レイ数 1.24 / 1.75 / 0.88 億、RMSE 0.0242 / 0.0242 / 0.0247、基準に対する平均輝度の比（R）0.9971 / 1.0002 / 1.0002。
- **観察**：ルーレットあり/なし（上限 64 回）で平均輝度が一致（バイアスなし）、RMSE もほぼ同じで、レイ数は半分、時間は約 1/2.1。上限 8 回は約 0.3% 暗いが、ノイズ（RMSE 約 0.024）に比べて小さい。1/p の補正を外すと、テストが失敗した。
- **保存先**：`experiments/2026-10-15_m4-russian-roulette/`、`docs/screenshots/2026-10-16_cornell-m4-*roulette*`
- **結論・次の一手**：有効。比較用に打ち切りが必要なときは `--rr` なしで、普段は `--rr` と大きな上限、が使える。

### 2026-10-16 — M4（MIS）/ 光源サンプリングと BSDF サンプリングの組み合わせ

- **目的**：2つのサンプリングを重みを付けて組み合わせ、光源の大きさによらず低ノイズにできるか確かめる。
- **実装変更**：`lightPdfSolidAngle()`、`bsdfPdfLambert()`（どちらも立体角あたり）、`powerHeuristic()`。NEE の寄与と、BSDF サンプリングで光源に当たった寄与の両方に重みを掛ける（`--mis` / `--no-mis`、**既定オン**）。
- **シーン・設定**：Cornell Box／光源の一辺 0.15 / 0.5 / 1.5 m（総電力一定）／8回反射／64 spp／ジッタ／シード 1／基準 = 各光源で MIS 1024 spp（シード 99）。Release ビルド。
- **比較条件**：同じ spp、および効率 = 1 / (MSE × 秒)。
- **計測**：RMSE（BSDF のみ / NEE / MIS）— 0.15 m: 0.370 / 0.1405 / 0.1405、0.5 m: 0.103 / 0.0246 / 0.0246、1.5 m: 0.0301 / 0.0159 / 0.0128。効率（1.5 m）: 276 / 608 / 932。
- **観察**：小さい光源では MIS ≒ NEE（BSDF 側の重みが 0 に近い）。BSDF のみは桁違いに悪い。**大きい光源で、MIS は NEE より約 20% 低ノイズ**（効率は約 1.5 倍）。3方式の期待値は、テストで一致を確認した（反射回数 1・2・3、光源 0.5 m と 1.5 m）。MIS の重みを入れ替えると、テストが失敗した。基準が MIS なので、MIS に少し有利な可能性がある。
- **保存先**：`experiments/2026-10-15_m4-mis/`、`docs/screenshots/2026-10-16_cornell-m4-*light*`
- **結論・次の一手**：MIS を既定にした（悪くなる場面がなく、大きい光源で良くなる）。つやのある面・鏡面で本領を発揮するはずだが、材質がまだ Lambert のみ（M7）。

### 2026-10-15 — M3 / プログレッシブ描画（段階的な蓄積）

- **目的**：画面を再起動せずにサンプルを追加でき、計算を続けるほど安定することを確認する。
- **実装変更**：サンプル番号の通し番号（`RenderSettings::firstSample`）、パスの計画（1→4→16→64→…→目標）、`RenderJob` のパス処理と画像の公開、`extend()`（リセットなしの追加）、GUI の進捗・`+ samples`・設定変更での自動リセット、`--progressive`。
- **シーン・設定**：Cornell Box／640x480／256 spp（パス 1, 4, 16, 64, 256）／ジッタ／シード 1／max depth 8／面光源 + NEE。
- **比較条件**：同じ設定の一括描画（256 spp）。
- **計測**：パスの完了時刻（累積、**Debug ビルド**）は 1.0 / 4.3 / 16.9 / 68.4 / 286.3 s。一括描画は 345.6 s。
- **観察**：段階描画と一括描画の PNG は**バイト単位で同一**（1ピクセルのサンプルが同じ順で足されるため）。テストでも、パスの分け方（1+3+1 など）によらず、フィルムが同一であることを確認した。1 spp で構図と色移りが分かる。
- **保存先**：`experiments/2026-10-15_m3-progressive/`、`docs/screenshots/2026-10-15_cornell-progressive-nee-*.png`
- **結論・次の一手**：M3 完了。時間は Release で測り直す。M4 の残りへ。

### 2026-10-15 — M4（NEE）/ 次イベント推定

- **目的**：光源への直接サンプリングで、同じサンプル数のノイズが減ることと、期待値が変わらない（二重計上がない）ことを確かめる。
- **実装変更**：`sampleDirectLight()`（各反射点で光源上の一様ランダムな点へシャドウレイ。寄与は `アルベド/π × 放射輝度 × cos(面) × cos(光源) × 面積 ÷ 距離²`）。BSDF サンプリングの経路が光源に当たっても足さない（カメラレイが直接見るときだけ足す）。`--no-nee` で M2 の方式に戻せる。
- **シーン・設定**：Cornell Box／640x480／spp 1・4・16・64・256／ジッタ／シード 1／max depth 8／基準 = NEE 1024 spp（シード 99）。
- **比較条件**：同じ spp、および誤差が同じになる時間。
- **計測**：基準画像との RMSE（NEE あり / なし）: 1 spp 0.179 / 0.819、4 spp 0.093 / 0.410、16 spp 0.047 / 0.205、64 spp 0.025 / 0.103、256 spp 0.013 / 0.052。時間は Debug で、NEE が1サンプルあたり約1.5倍（Release でも同じ比: 256 spp で約 26 s / 17 s）。
- **観察**：どちらも 1/√N で減る。同じ spp の誤差は約 1/4（= 同じ誤差に必要なサンプルは約 1/16）。NEE の 16 spp は NEE なしの 256 spp と同等の画質で、時間は約 1/10。NEE あり / なしの期待値は、テストで一致を確認した（反射回数 1・2・3、標準誤差の5倍以内）。
- **保存先**：`experiments/2026-10-15_m4-nee/`（`run.sh`、JSON、`notes.md`）、`docs/screenshots/2026-10-15_cornell-path-nee-8bounce-*.png`
- **結論・次の一手**：NEE は有効。M4 の残り（Russian Roulette、MIS）へ。MIS の効果は、大きい光源や、つやのある面で見える（今は Lambert のみ）。

### 2026-10-15 — M2 / 最小のモンテカルロ・パストレーシング

- **目的**：直接照明だけでは出なかった間接照明・カラーブリーディングを確認し、サンプル増加で収束することを確かめる。
- **実装変更**：`pathTrace()`（Lambert、コサイン重み付き半球サンプリング、面光源の解析的な交差、反射回数の上限、環境光 `--env`）。Classic（Whitted）のコードは使わない（二重計上なし）。`--integrator classic|path`。`Scene/Test/Cornell.glb`（`tools/make_cornell.py`）。
- **シーン・設定**：Cornell Box（赤壁・緑壁・白い箱2個・0.5 m の天井の面光源）／640x480／256 spp／ジッタ／シード 1／反射回数 0・1・2・4・8／NEE なし。
- **比較条件**：反射回数の違い。spp は、8回反射で 1・4・16・64・256 の、256 spp との RMSE。
- **計測**：画像全体の平均輝度（R/G/B）: 0回 0.103、1回 0.154/0.149/0.143、2回 0.178/0.170/0.159、4回 0.196/0.184/0.168、8回 0.202/0.189/0.170。256 spp との RMSE: 1/4/16/64 spp で 0.82 / 0.41 / 0.20 / 0.089。
- **観察**：1回反射では天井が真っ暗。2回以上で壁の色が箱や天井に移る（背の高い箱の赤、低い箱の緑）。4→8回の増加は約3%（反射回数の上限による暗さの偏り）。NEE なしでは、256 spp でもざらつく。誤差は4倍のサンプルで約半分。
- **保存先**：`experiments/2026-10-15_m2-cornell/`、`docs/screenshots/2026-10-15_cornell-*.png`
- **結論・次の一手**：M2 完了。NEE（M4）と M3（プログレッシブ）へ。

### 2026-10-15 — 保守 / 輪郭の黒い点の修正

- **目的**：金属球・ガラス球の輪郭に出ていた真っ黒な点（M0 の基準画像から含まれていた不具合）を直す。
- **実装変更**：表裏の判定を、補間した法線ではなく三角形の向き（幾何法線）で行う。補間した法線が輪郭でカメラと反対向きになる場合は、ほぼ接線（cos = 0.01）に補正する。旧方式は `--legacy-normals` で残した。
- **シーン・設定**：Room_2Spheres / Untitled／1 spp（ピクセル中心）と 64 spp（ジッタ）／点光源と面光源。
- **比較条件**：旧方式との、画素単位の厳密な比較。
- **計測**：1 spp で、変わったのは 21 / 30万ピクセル（0.007%）、真っ黒なピクセルは 14 → 0（2球）、6 → 0（3球）。64 spp では 459 ピクセル（0.149%）が、わずかに明るくなった（最大 0.086）。
- **観察**：旧方式の欠陥は、多サンプルの平均で黒い点としては見えなくなっていたが、輪郭を少し暗くしていた。輪郭から遠いレイは、1ビットも変わらない。`--legacy-normals` で、M0 の基準画像と過去の実験を、ビット単位で再現できる。
- **保存先**：`experiments/2026-10-15_silhouette-fix/`
- **結論・次の一手**：補正値の調整と複雑なメッシュでの確認は、必要になったときに。M2 へ。

### 2026-10-15 — M1 実験 / 光源の大きさ × サンプル数

- **目的**：M1 の完了条件（光源サイズに対応して半影が変化し、サンプルを増やすとノイズが減る）を、画像と数値で確認する。
- **実装変更**：なし（実験のスクリプトと解析のみ）。
- **シーン・設定**：Room_2Spheres／640x480／面光源の一辺 0.25 / 2 / 4 m（総電力は一定）／spp 1・4・16・64（基準は各サイズ 512）／ジッタなし／シード 1・777／max depth 6。
- **比較条件**：各サイズの 512 spp 基準画像との差（RMSE）、床の上の影の縁の幅（10%〜90%）。
- **計測**：半影の幅（床の上）は 0.043 / 0.266 / 0.513 m（光源 0.25 / 2 / 4 m）。幅 ÷ 光源の大きさは、2 m と 4 m で 0.133 / 0.128 とほぼ一定。1 spp の RMSE は 0.049 / 0.157 / 0.168、64 spp で 0.0059 / 0.0184 / 0.0237。どのサイズでも、サンプル4倍で誤差は約 1/2。
- **観察**：半影の幅は光源の大きさに比例する。光源が大きいほど、同じサンプル数でのノイズが多い（増え方は頭打ち）。小さい光源は、少ないサンプルで足りる（0.25 m の 1 spp ≈ 2 m の 16 spp）。0.25 m の幅は 1 ピクセル未満で、測定の分解能の限界。
- **保存先**：`experiments/2026-10-15_light-size-spp/`
- **結論・次の一手**：M1 完了。M2（最小のモンテカルロ・パストレーシング）へ。拡散面どうしの間接光（カラーブリーディング）を、初めて扱う。

### 2026-10-15 — M1 手順3 / 面光源のサンプリングと直接照明の推定

- **目的**：矩形の面光源をランダムにサンプリングして、ソフトシャドウを描く。
- **実装変更**：`sampleLight()`（光源上の一様ランダムな点、重み = 放射輝度 × 面積 × cos(光源側) ÷ 距離²、片面発光）。`LightMode { Point, Area }`（点光源 = M0 の基準方式を残す）。`configureLight()`（光源の一辺を変えても総電力は一定）。`--light` / `--light-size`、パネルの光源の項目。`rt_radiance` を 11.56 に較正（部屋の中心の床で、矩形全体の平均が旧点光源と同じ明るさ）。
- **シーン・設定**：Room_2Spheres／640x480／面光源 2 m × 2 m／ジッタなし／spp 1〜256（基準は 1024）／シード 1／max depth 6。
- **比較条件**：面光源 1024 spp の基準画像との差（RMSE）、点光源（M0）との見た目の比較。
- **計測**：RMSE は 1 → 4 → 16 → 64 → 256 spp で 0.157 → 0.069 → 0.035 → 0.018 → 0.0096（サンプル4倍ごとに約 1/2）。点光源 0.265（照明が異なる）。1spp の時間は点光源の約 +15%（92 → 109 ms）、レイ数は同じ。
- **観察**：影の縁が半影になる。1spp では半影がざらつき、サンプルを増やすと滑らかになる。点光源モードは、M0 の基準とビット単位で同一。推定器は、独立に作った数値積分と 1% 以内で一致し、光源の半分を遮ると明るさがちょうど半分になる。金属球・ガラス球の輪郭に、数ピクセルの黒い点（輪郭で補間した法線が反転して、レイが球の内側で跳ね返り続け、0 になる。以前からの問題。詳細は WORKLOG の「黒い点の調査」）。
- **保存先**：`experiments/2026-10-15_area-light-spp/`
- **結論・次の一手**：光源の大きさ（小・大）× サンプル数（1/4/16/64）の実験で、M1 の完了条件（光源サイズに対応して半影が変化する）を確認する。

### 2026-10-15 — M1 手順2 / 乱数とサンプラ（ジッタによるアンチエイリアス）

- **目的**：再現性のある乱数を入れ、最初の利用として、ピクセル内のランダムな位置のサンプリング（モンテカルロ積分）を確かめる。
- **実装変更**：PCG32 と `Sampler`（(シード, ピクセル, サンプル) ごとの独立した列）、`--spp` / `--jitter` / `--seed`、`--rmse`（画像の差）。`trace()` が `Sampler` を受け取る（未使用）。
- **シーン・設定**：Room_2Spheres／640x480／spp 1〜256（基準は 1024）／ジッタ／シード 1／max depth 6／点光源。
- **比較条件**：参照画像（1024 spp）との差（RMSE）。
- **計測**：RMSE はジッタ 1 → 4 → 16 → 64 → 256 spp で 0.0199 → 0.0096 → 0.0047 → 0.0024 → 0.0015（サンプル4倍ごとに約 1/2）。ピクセル中心 1spp は 0.0099。時間は spp にほぼ比例（87 ms → 約 20 秒）。
- **観察**：誤差は 1/√N で減る（理論どおり。最後の段は基準画像のノイズの影響）。ジッタ 1spp は、ピクセル中心 1spp より誤差が2倍大きい（バイアスをなくす代わりにノイズが増える）。4spp でほぼ同等、16spp から良くなる。既定設定の画像は、M0 の基準とビット単位で同一。
- **保存先**：`experiments/2026-10-15_sampler-aa/`（`run.sh` で再生成、`edges.png` に輪郭の拡大比較）
- **結論・次の一手**：手順3（面光源のサンプリングと直接照明の推定）へ。同じ 1/√N の性質が、半影のノイズにもそのまま現れるはず。

### 2026-10-15 — M1 手順1 / 面光源の定義と読み込み

- **目的**：矩形の面光源をシーンデータに持たせ、レンダラに読み込む（描画への利用は次の手順）。
- **実装変更**：GLB の `Area_Light` ノードの extras（`rt_light_type` / `rt_size_x` / `rt_size_y` / `rt_radiance`）と変換から、位置・辺ベクトル・法線・面積・明るさを読む（`AreaLight`）。描画は従来どおり、面光源の中心の点光源。
- **シーン・設定**：Untitled / Room_2Spheres。面光源は 2 m × 2 m、`rt_radiance` = 15（仮。手順3で較正）、中心 (-4, 5, 2)、発光の向き (0.667, -0.667, -0.333)。
- **比較条件**：基準画像との同一性（ビット単位）。
- **観察**：画像は2シーンとも基準と完全に同一（期待どおり）。発光の向きは、最初に「ローカル -Y」と誤って仮定し、Blender 側の値との照合で間違いに気づいた。正しくは「ローカル -Z」（glTF のカメラ・ライトと同じ）。テストに、Blender 側の値との照合を入れた。
- **保存先**：`experiments/2026-10-15_baseline/`（面光源の定義を JSON に追加して再生成）
- **結論・次の一手**：手順2（乱数とサンプラ）へ。

### 2026-10-15 — M0 / 現行実装の基準化
