# 法線マップの向きの規約を、Blender と数値で比べる

- 日付: 2026-10-17
- 目的: 自作レンダラの法線マップ(`applyNormalMap`、接線は UV から自前で計算)が、**Blender の書き出し(UV の上下反転を含む)を通しても**、Blender と同じ向きになるかを確かめる。緑チャンネルの上下(OpenGL か DirectX か)、タンジェント空間の手の向き、v の向きの取り違えを検出する。
- 方法(`run.sh`、手順 1 は手動):
  1. Blender で `nm_blender.py` を実行: 2 m の平面(+Z 向き)に、2x2 の法線マップ(画素 = 左下 (0.6, 0, 0.8)、右下 (0, 0.6, 0.8)、左上 (-0.6, 0, 0.8)、右上 (0, -0.6, 0.8) のタンジェント空間の向き)を付け、Blender のエクスポータで glb に書き出す(`out/nm_test.glb`)。同じ法線マップの法線を、**Blender 自身が計算した値**として、真上の平行投影カメラ + 発光(法線 × 0.5 + 0.5)で、64x64 の画像にする(`out/nm_test_aov.npy`)。
  2. `nm_probe.cpp`: その glb を自作レンダラのローダで読み、同じ位置から真下に光線を飛ばして、`applyNormalMap` 後の法線(と、緑を反転した場合の法線)を書き出す。
  3. `compare.py`: Blender の法線(Z 上 → glTF の Y 上に変換)との角度を測る。
- 結果(テクセルの中心の ±2 画素、n = 64): 角度の差は、**実装どおり: 中央値 2.91°、最大 4.22°**。**緑を反転: 中央値 36.97°、最大 72.18°**。各象限の法線は、Blender と同じ向き(例: 左下 = 自作 (0.561, 0.827, -0.022)、Blender (0.598, 0.801, -0.004)、glTF の座標)。**向きの規約は、Blender と合っている**。
- 残る数度の差の原因(**推定、未検証**): 窓が ±2 画素なので、双線形補間で隣のテクセルが少し混ざる(Blender 側は最近傍)。画素の中心のずれ。
- 傾きの大きさ: テクセルの中心以外では、自作のほうが傾きが小さい(例: 象限の内側の全画素で、中央値 15.3°)。**自作レンダラは常に双線形補間で、隣のテクセルと混ざる**ため(2x2 の画像で目立つ。サンプラーの `NEAREST` は読まない)。バグではなく、未対応の機能(サンプラー)の影響。
- **最初に試した方法(うまくいかなかった)**: ビートルの実物のクローズアップ 2 視点(後輪、座席と計器盤)で、Blender の法線(上書きマテリアルで法線を発光させて取り出す)と比べた。**結果は判定不能**: ビートルの法線マップは、見えている範囲でほぼ平らで(法線を 8° 以上動かす画素は 0.01%、1.7% は縁のアンチエイリアス)、向きの違いが出なかった。「差が大きい画素」に見えたものは、ほぼ、斜めに当たる縁の画素の、表と裏の反転だった。この結果は、`experiments/2026-10-16_beetle/notes.md` にも書いた。
- 注意: この検証で、Blender の MCP 経由のスクリプトの変数が、`exec` した別のスクリプトの変数に上書きされる事故があった(Blender の状態は、元のままだった。以後、`exec` は別の名前空間で行う)。
